# The conformance engine

> **Deep reference for the shipped implementation.** Canonical concepts and the target design live in the [documentation corpus](README.md); what is shipped versus target is owned by [status-and-compatibility.md](status-and-compatibility.md).


CI for the vault: a headless TypeScript engine (`packages/conformance/src/kernel/`, the `vaultmcp-conformance` plugin; it was `packages/host/src/conformance/` until 2026-10-14) that
runs **rule packs** over a snapshot of the vault and diffs the findings against an accepted
**baseline**, so only *new* drift alarms. It implements the project's "checks before gates"
principle — the conformance rail arms the acceptance gate rather than nagging about
pre-existing debt. Landed in stages: the Phase-1 engine (#89), the ported legacy checks
(#103), and the final `drift_audit` port (#127/#130); everything is TS per the no-Python
ruling — the engine replaced the loose Python rail scripts, whose retirement is complete.
(These docs track `main`, not a release.)

## Shape

| Piece | What it does |
| --- | --- |
| `finding.ts` | The finding record and its **4-tuple key** `(script, check, target, kind)` — byte-compatible with the pre-existing baseline format, so accepted debt carried over without re-blessing. |
| `rule-pack.ts` | The pack contract: *the engine feeds a listing, the pack returns typed findings.* Packs are pure functions — no vault reads inside a pack. |
| `snapshot.ts` | Headless disk source: parses frontmatter/bodies into the listings packs accept (reuses `@vault-mcp/core` parsing; accepts an `excludedRoots` exclusion list — wired from the invocation via `--exclude=`/`GOVERNOR_EXCLUDED_ROOTS` (legacy `ASSENT_EXCLUDED_ROOTS`), with `excludedRootRefusal` refusing a run whose exclusions would strand accepted baseline keys). Also the territory chokepoint (#157): `buildSnapshot` refuses a root with no declared boundary, a root resolving outside it, and a root or symlink resolving into one of the operator's guarded territories (`--territory=`/`GOVERNOR_TERRITORIES` on the CLI, inside Obsidian the host's `guardedTerritories` setting, which the plugin reads through the host api per run; NO built-in list since #397). A listed territory met INSIDE the root is skipped and reported, not refused (#398), and a baseline key under a skipped folder refuses the run rather than reading CLEARED — decided over resolved real paths (`path-identity.ts`), before any read. |
| `engine.ts` | Runs the registered packs over a snapshot. |
| `ratchet.ts` | Baseline diff: **NEW / CLEARED / CARRIED** per finding key. New findings gate; carried ones are accepted debt burning down on the human's schedule. |
| `cli.ts` | The testable rail core (`runConformance`) + `runCli` (argv/env/read/write). The debt sidecar reconcile + trend append + budget teeth live here (#211). |
| `main.ts` | The process entry. From `packages/conformance`: `node --import tsx src/kernel/main.ts …` (or `npm run conformance -- …`). Split from `cli.ts` so the importable core carries no `import.meta` (the plugin bundles `runConformance` for the debt tools and the Drift pane). |
| `debt-sidecar.ts` / `debt.ts` / `debt-trend.ts` | The debt register data layer (#211): the per-key metadata sidecar, the read-only report core (carried items + burn-down + staleness/budget teeth), and the append-only trend log. |
| `debt-register.ts` | The human-facing register render (#211 Part B): a pure builder that materializes the debt report as ONE generated vault note (`Conformance debt.md`, default beside the baseline) — summary header, carried-debt table (each row linked to the offending note, stale + high-priority first), and a "cleared — prune these" section; the two lists share one budget of 200 findings (a larger `registerMaxRows` is clamped) with a "+N more" line, and the note stays under 256 KB (report cap 1). Frontmatter is a `generated`/`generator` derivation stamp, never an acceptance field (accept-guard-checked before every write). CLI: `--render-register` (plus `--register-dir=`/`GOVERNOR_REGISTER_DIR`, `--stale-after=`/`GOVERNOR_STALE_AFTER_DAYS` (legacy `ASSENT_*` spellings also recognized)); a `--rebaseline` refreshes an *existing* register automatically but never creates one unasked. MCP: the mutating `vaultmcp_conformance_debt_render` (refused by the host while a path allowlist is active). No `.base` file is generated: Obsidian Bases query notes/frontmatter, so a multi-row Base would need one stub note per debt item — exactly the note-per-item spam the design rejects; the table + the JSON sidecar are the register. |
| `report-caps.ts` / `audit-output.ts` | The size caps (2026-10-15, "Replace the four Forge-only checks"): the register note in the vault lists at most 200 findings, then one "+N more" line, and stays under 256 KB, and the debt tool returns at most 200 carried items and 200 stale keys; the CLI run writes the full finding set to a JSON file outside the vault (`--findings-json`, default `~/.local/share/vault-audits/`, refused inside the vault) and states what it checked; the CLI run and the debt tool both replace an output over 5 MB by its counts (the tool marks it `output_capped`); the register and the debt tool state what they checked when their source supplies coverage. `report-caps.ts` is pure (tools.ts imports it); `audit-output.ts` holds the two path functions that read the filesystem. |
| `shapes/` | Forge's shape derivation and heading matcher (nl.11 plus forge#5), ported under the MIT notice in `shapes/LICENSE` for the `shape` pack: `## Shape` or `## Template` fence extraction, the generator-to-wildcard derivation with the optional leading `# {{TITLE}}`, the fence- and comment-aware heading scanner, and the per-level match and order check. |
| `packs/` | The rule packs (below). |

## Rule packs

- **Native** — `scheme.ts` (the scope module's `schemeFindings`: addressing/structure drift; it runs only when the host has a scheme configured, read from the host's settings — none on a fresh install, see [scope-provider.md](scope-provider.md#turning-a-scheme-on))
  and `vocab.ts` (unregistered tags, undefined properties, unknown types, deprecated terms).
  `vocab.ts` wraps `noteVocabFindings` per note and runs `vocabularyFindings` once per pass (the `## Tags` table lint and `scope_root_missing`). Both live in **`@vault-mcp/core`** since the S7
  read-tier extraction: this rail and the `vaultmcp-vocab` satellite are its two consumers, and
  a second copy of a vocabulary rule core is how one vault gets two vocabularies. Note that
  this rail builds its registry from `DEFAULT_VOCABULARIES` rather than from the configured
  instance list — a pre-existing gap the extraction makes visible, not one it introduced.
- **Ported legacy checks** (#103, completed by `drift.ts` in #127/#130) — `structure.ts`,
  `port.ts`, `ste.ts`, `drift.ts`: line-for-line ports of the Python originals,
  **parity-verified against the live Python before trust** (finding keys diffed both
  directions, zero divergence at port time). `legacy-scope.ts` preserves each script's
  deliberate per-script scope variance rather than flattening it. The Python rail is
  retired, so parity is now historical: where the port's byte-parity preserved a defect,
  the TS packs fix it against their own semantics — frontmatter recognition binds to
  core's shared fence recognizer rather than the Python's literal `---` scan (#189, #223,
  and #227 for `ste`), and `structure.ts` reports an `UNRESOLVED-INCLUDE` finding where
  the Python silently shrank a blueprint's emitted-H2 set on an unresolvable
  `{% include %}` (#112). Deliberately-kept legacy behaviors (ASCII word boundaries,
  last-in-sorted-order blueprint basename arbitration) are pinned by comment + test
  rather than silently relied on (#112). Since #412 `drift.ts` is two of the Python's checks, E and J; the others measured a vault shape the rebuilt vault no longer has and are retired (see the honest-status bullet below), so its parity is historical for those.
- **The Forge replacements** (2026-10-15; the vault task "Replace the four Forge-only checks", which Nelson verified on 2026-10-14 with the pick that the checks live in this plugin, not the host). Check (a), shape lint, is the new `shape` pack (`packs/shape.ts`): for each note whose `type` names a class note under the `fileclassesRoot` convention, the class's `## Shape` fence, or the shape derived from its `## Template` fence, gives the required headings, and the pack reports `missing_heading` and `heading_order` (keyed on the note path, the class and the heading, never a line number). A class with neither fence is one `unchecked_class` finding, never read as clean, and a `type` that names no class is `unbound_type`. Extra headings and empty sections are not carried. Check (b), the uid and date rules of `00.92 Forge schema`, extends `drift.ts` with K (a note with no `uid`, one finding per note) and L (`created` or `modified` missing, or not `YYYY-MM-DD[THH:MM[:SS]][offset]`; fractional seconds stay rejected); the 00.92 severity (uid error, created warning, modified info) is in the finding's `detail`, because the finding shape has no severity field. Check (c), key reordering, is a 00.13 script in the vault, not a pack. Check (d), repair, has no rows on its written list yet, so there is no repair mode: every finding goes to an acceptor. The parity baseline for (a) (a run of `shape-source-proof-harness` before Forge is uninstalled) is a vault step and is not in this repo.

## Honest status

- The legacy packs **register by default** (`--no-legacy-packs` opts out): the accepted-debt
  baseline's keys are exclusively legacy-pack keys, so a run without them would report the
  entire baseline as CLEARED — a false "all debt fixed" (#116; the rationale is on
  `RunOpts.legacyPacks` in `cli.ts`).
- A **dead convention path is loud** (#298): every path-valued key of the vault conventions is checked against the walk before the legacy packs run; a key that names nothing becomes a `conformance_engine / dead_convention` finding (NEW, so the run fails), every pack that reads it is registered but not run and not counted as covered, and the report prints `DEAD CONVENTION: <key> = <path>`. An engine finding is never rebaseline text — it describes the run, not the vault — so a dead convention is NEW on every run and cannot be silenced through `--rebaseline`; when the baseline names an unmeasured pack, the coverage refusal says which convention is dead and how to set it. Nothing guesses a replacement path — where a convention should point is a vault filing question, answered by the operator. **Since #403 (ruled 2026-09-26) the conventions are a setting** (`vaultConventions`, one field per key), shipped EMPTY. They were a host setting on the host's Conformance tab until 2026-10-14; they are now the `vaultmcp-conformance` plugin's, on its own settings tab, adopted once from the host's data.json (see [The plugin](#the-plugin)). Shipped EMPTY means: a blank scalar key is a dead convention and its packs are not measured, an empty list key is "none". An install that predates the setting is seeded once with the former shipped paths (`LEGACY_CONVENTIONS_SEED`, one reader), so an upgrade changes nothing for it. The in-app debt and drift sources read the setting per call; the standalone CLI reads `VAULT_MCP_CONVENTIONS` (a JSON object over the same keys; `GOVERNOR_VAULT_CONVENTIONS` and `ASSENT_VAULT_CONVENTIONS` are read as legacy aliases for one release, with a warning). As of 2026-09-24 every former shipped path but `systemRoot` was dead on this vault (two renumberings since they were written), which is why they stopped being a default. **Since #412 (ruled 2026-09-27: "retire the four drift_audit checks — the fileclass system is their replacement") the record has three keys**: `registriesRoot` (the structure pack's blueprint registry), `systemRoot` (drift's category-collision scan) and `ungovernedRoots`. The drift pack's checks A, B, D, F and G measured a vault shape the rebuilt vault no longer has (the `.action`/`.property`/`.type`/`.tag` registry families, the plugin-stack table note, the artifacts root, the uid-exempt template); they are retired, and with them the keys `artifactsRoot`, `pluginStackPath` and `uidExemptPaths` are gone from the record (a stale data.json that still carries them coerces to the three). Drift keeps E (duplicate uid, no exemption) and J. **Since #493 a fourth key, `baselineRel`**, names the accepted-debt baseline note (it was a constant in cli.ts). It feeds no pack and is never a dead convention: blank means no baseline is configured, and then the in-app debt tools and drift pane and the CLI refuse rather than report every finding as NEW. Before #493 every install read a baseline, so an install whose stored conventions lack the key takes, once, the path it was reading: the `GOVERNOR_BASELINE_REL` override when one is set (also for an install that predates #403), else the old constant's path when some other key is set or that note exists in the vault; an all-blank record in a vault without that note (a fresh install) stays without one. In-app, the setting wins over the `GOVERNOR_BASELINE_REL` environment override; the CLI reads the override first, then its `VAULT_MCP_CONVENTIONS`, then the path the plugin derives from its data.json in the vault (the `vaultmcp-conformance` data.json when it holds the conventions, else the host's `vault-mcp` data.json by the rule the plugin adopts by; a data.json that predates the key gives the path the plugin will fill). `--rebaseline` refuses a target that is any live baseline it can see (the CLI's path, the `VAULT_MCP_CONVENTIONS` path when the override shadows it, the plugin's), and refuses outright when none names one. The retired checks' accepted keys in a live baseline are no longer produced and read CLEARED on the next run, since the coverage refusal works at pack granularity; the report names them (`RETIRED CHECK: N of the M cleared key(s) …`) so they are not read as repairs; pruning them is a human act, the reviewed-copy procedure below (`--rebaseline` refuses the live acceptance record by design).
- Both in-app adapters (`vaultmcp_conformance_debt`, the Drift pane) apply **`coverageRefusal`** after their run (#294), the same exported function `runCli` uses: a pack the baseline describes that did not run — threw, or its convention path is dead — refuses rather than reporting its accepted keys CLEARED.
- Rebaseline safety is **computed, not hardcoded** (`rebaselineRefusal` in `cli.ts`,
  replacing the retired `PHASE1_PACKS_INCOMPLETE` constant whose stated reason expired
  silently): a rebaseline refuses when the baseline names a pack the run didn't register
  (it would silently drop that pack's accepted keys), and a rebaseline targeting the LIVE
  baseline refuses — it is an acceptance record, and acceptance is a human gesture. An explicit
  `--baseline=<fixture>` path is how a rebaseline is reviewed before a human applies it.
- **`fileclassesRoot` ships blank, so `shape` is not measured until the operator names the fileclasses folder.** A blank key is a dead convention: the `shape` pack registers but does not run, the run carries a NEW `dead_convention` finding, and the report says `DEAD CONVENTION: fileclassesRoot = (empty)`. That holds for an existing install too, whose stored conventions predate the key; no folder name is seeded. Once it is set, the shape and K/L findings show as NEW until a human-reviewed rebaseline takes in the carried ones.
- Pack fixes that recognize more than the retired Python did (e.g. #227's BOM-aware `ste`
  frontmatter exemption, #112's `UNRESOLVED-INCLUDE`) can shift or add finding keys; those
  surface as NEW and are blessed — or fixed — at the next human-reviewed rebaseline rather
  than auto-accepted.

The pack registry is a plain list today; it subscribes to the module config-host when that
lands, and pack capabilities join each module's capability directory.

## The plugin

Since 2026-10-14 the rail is its own Obsidian plugin, `vaultmcp-conformance` (`packages/conformance`), as the suite-split design planned (Nelson, 2026-10-14: "the conformance and scheme features still in core (i see em on the settings pages) need to be split out into satellites"). The scheme surface stays in the host by the 2026-09-05 ruling. The plugin has four parts:

- **Two MCP tools**, published to the host through `vault-mcp-api`: `vaultmcp_conformance_debt` (the read-only debt report; it was `obsidian_conformance_debt`) and `vaultmcp_conformance_debt_render` (writes the register note; it was `obsidian_conformance_debt_render`). Behaviour, arguments and refusal codes are those of the host tools, with one added refusal code, `invalid_argument`, for an empty filter or a `group_by` outside its list. Neither tool takes an argument the host reads as a path, so the host refuses both while a path allowlist is active. In the host the report ran over the whole vault under an allowlist and the render refused only when the register path was outside it. With no allowlist nothing changes. This takes the last tool off issue #381's list.
- **The Drift pane**: the scheme pack's new findings, grouped by check. It has its own ribbon icon and command ("Open conformance drift"), and it is not mounted when the host's headless mode is declared.
- **The settings tab**: the vault conventions (the host's former Conformance tab, unchanged) and the debt register settings (`staleAfterDays`, `debtBudget`, `strictBudget`, `registerDir`, `registerMaxRows`), which in the host were a hand edit of `modules["conformance-debt"].config`.
- **The CLI**, run from the package (see `main.ts` above).

On its first load with the host present, the plugin copies the host's `vaultConventions` and `modules["conformance-debt"].config` into its own data.json, once, and does not write the host's settings. A host record without `vaultConventions` gives the former shipped paths only when the legacy baseline note exists in the vault, and is EMPTY otherwise. The guarded territories stay the host's: the plugin reads them through the host api per run, and refuses to run when no host answers.
