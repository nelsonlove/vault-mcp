### Section 2's governance rows — MOVED to the governance provider (S3c)

Three always-on rows stood here until the host/governor split: the pending-review listing (`tools-pending-review.ts`, kernel B3b) and the two revision tools (`tools-governance-revision.ts` — `registerGovernanceRevisionTool` / `registerGovernanceRevisionsListTool`, #101/#221). Two mandate tools sat beside them in source and were never written up here at all. All five now live in `packages/governor/src/tools/` and are PUBLISHED into this host through `vault-mcp-api`, exactly the way a third-party plugin publishes.

**Their names did not change**, and that is a deliberate, closed exception rather than a pattern. The ordinary publishing rule is `<sanitized owner id>_<bare name>`, and the host REFUSES any published name beginning `obsidian_` (`external-tools.ts`'s F1 check) — the rule that forced the seven `obsidian_jd_*` renames. Under it the revision tools would have become `governor_governance_revisions` and the pending-review tool could not have been published at all. So `external-tools.ts` carries `GRANDFATHERED_TOOL_NAMES`: a checked-in map from each of the five spellings to the SINGLE owner id (`governor`) permitted to publish it. Nothing else reaches the reserved namespace, no publisher-controlled flag exists that could claim one, and the table is closed — a new tool takes the ordinary namespaced form. It exists only for continuity of names that were already on the wire when the split happened.

The names are deliberately not backticked in this file: the source↔doc lock scrapes backticked `obsidian_*` names and would read a departed one as a name this host ought to register. `packages/governor/TOOL-INVENTORY.md` carries all five in full, with their published spellings, their read-only hints, and their allowlist posture under this host's gate — which got STRICTER in the move, the same way it did at every previous extraction: an external tool's read-only claim is distrusted unless the operator lists `governor` in `trustedReadOnlyPlugins`, and under an active path allowlist the F3 gate refuses any external tool whose arguments carry no recognized path key.

`tools-import.ts` — `registerImportTools` (#252). Drives the STOCK community
obsidian-importer plugin's Apple Notes importer headlessly: null-element

journal, kernel args and read-only-mode blocking; `output_folder` is a
recognized `PATH_KEYS` name and schema-defaulted, so the guard
allowlist-checks it, the journal records it as the target, and advisory
locks over it are disclosed. `dry_run` (mandatory) reports the folder
